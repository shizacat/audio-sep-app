# Требования к разработке

## Цель

Приложение открывает аудиозапись, принимает текстовое описание звука и сохраняет отделённый результат. Разделение выполняет AudioSep. Этот репозиторий отвечает за окно, фоновый запуск и показ ошибок.

## Стек

- Python 3.12+.
- Qt 6 через PySide6. Другие биндинги Qt не используются.
- Тесты — pytest. Стиль — Ruff.
- Разделение звука делает [AudioSep](https://github.com/Audio-AGI/AudioSep).

## Окружение

Зависимости объявлены в `pyproject.toml`. Ставит их [uv](https://docs.astral.sh/uv/) в `.venv` в корне репозитория, интерпретатор — Python 3.12 из `.python-version`. `.venv` в git не входит. `uv.lock` в репозиторий не входит: список зависимостей ведётся только в `pyproject.toml`.

```shell
uv sync
```

В `[project.dependencies]` — то, что нужно приложению при запуске. В группе `dev` — проверка кода и сборка пакета. `uv sync` ставит обе группы.

Окружение приложения — только этот `.venv`. Каталоги и окружения вне репозитория не используются.

## Запуск

Из корня репозитория:

```shell
uv run audiosep-app
uv run audiosep-app --log-level debug
uv run audiosep-app --separator /path/separator.onnx --clap /path/clap_text.onnx
```

Команда открывает окно. Так запускают приложение при разработке и при ручной проверке. В окне выбирают аудиофайл, указывают звук, который нужно отделить, и нажимают «Отделить». Отделённая дорожка сохраняется рядом с исходником, к имени добавляется `_separated`. Если включена галка «Убрать отделённый звук из оригинала», рядом сохраняется и запись без этого звука, с суффиксом `_without`. Под галкой всегда виден текст: отделённый звук сохраняется с суффиксом `_separated`, а при включённой галке вычитается из исходной записи в файл `_without`. Имена файлов не спрашиваются. Кнопка «Открыть папку» открывает каталог с этими файлами. Разделение идёт в фоне. Закрытие окна завершает процесс.

`--log-level` задаёт уровень корневого логгера: `debug`, `info`, `warning`, `error`, `critical`. По умолчанию `info`. `--separator` и `--clap` задают файлы моделей. Без них берутся пути по умолчанию из раздела «Модели». Остальные аргументы командной строки передаются в Qt, например `-platform offscreen`.

## Распространение

Готовое приложение — каталог, собранный PyInstaller. PyInstaller собирает приложение на Qt 6. Внутри свой интерпретатор и зависимости из `[project.dependencies]`. Отдельный Python на машине пользователя не нужен. Сборка выполняется на целевой ОС. Группа `dev` в пакет не входит.

Собираются Linux, macOS и Windows. Та же команда запускается локально на целевой ОС и в GitHub Actions (`.github/workflows/package.yml`). На macOS результат — отдельный образ под архитектуру машины сборки, не универсальный файл: `dist/AudioSep-macos-arm64.dmg` или `dist/AudioSep-macos-x86_64.dmg`. Внутри `AudioSep.app` и ссылка на «Программы». Каталог `models` лежит в приложении рядом с исполняемым файлом, а не рядом с `AudioSep.app`: при запуске из образа macOS копирует только пакет во временный каталог и не забирает соседние файлы. В Actions собираются оба: `macos-latest` для Apple Silicon и `macos-15-intel` для Intel. На Windows результат — `dist/AudioSep-windows.zip`: внутри каталог `AudioSep` с `AudioSep.exe` и `models` рядом. На Linux результат — `dist/AudioSep-linux.zip`: внутри каталог `AudioSep` с исполняемым файлом `AudioSep` и `models` рядом. Каталог `build/` — рабочий каталог PyInstaller, файл `build/audiosep/AudioSep` приложением не является.

Workflow запускается только при отправке git-тега. Экспорт ONNX — одно задание `onnx` на `ubuntu-latest`. Оно скачивает чекпоинты, запускает скрипты из `script/` и передаёт `separator.onnx` и `clap_text.onnx` артефактом `onnx-models`. Сборки Linux, обеих архитектур macOS и Windows зависят от этого задания и идут параллельно. Экспорт при этом не повторяется.

Из корня репозитория, после `uv sync`:

```shell
uv run python bundle/build.py
```

Запуск собранного приложения:

```shell
open dist/AudioSep-macos-arm64.dmg
```

Запуск из образа macOS: двойной щелчок по `AudioSep.app`. Модели уже внутри приложения, дополнительные аргументы не нужны. На Windows архив распаковывают и запускают `AudioSep.exe`. На Linux архив распаковывают и запускают `AudioSep`. В обоих архивах каталог `models` лежит рядом с исполняемым файлом. Другие модели задаются аргументами `--separator` и `--clap`.

Пакет не подписан. macOS может спросить подтверждение при первом открытии скачанного архива. Windows может показать предупреждение SmartScreen.

Локальная сборка берёт `separator.onnx` и `clap_text.onnx` из `local/` и кладёт их в `models` пакета. Если файла нет, сборка останавливается. В Actions те же файлы перед сборкой скачиваются в `local/` из артефакта задания `onnx`.

## Подзадача ONNX

Каталог `script/` не входит в приложение и не ставится в его `.venv`. Окружение скрипта — `../AudioSplit/.venv` у соседнего клона AudioSplit. Как запускать экспорт, написано в `script/README.md`.

Прогон моделей — библиотека `audiosep_app.infer.OnnxSeparator`. На вход моно-волна 32 кГц и текст, на выход волна той же длины. Командной строки и окна у библиотеки нет. Окно вызывает её через адаптер в `src/audiosep_app/separation/`. Токенайзер RoBERTa лежит в пакете и не скачивается при запуске.

В GitHub Actions то же экспорт делает задание `onnx`. Чистое окружение этого задания ставит пакеты из `script/requirements-ci.txt`. Код AudioSep для экспорта клонируется только на бегуне и в приложение не входит.

## Модели

При разработке файлы `separator.onnx` и `clap_text.onnx` лежат в каталоге `local/` в корне репозитория. Этот каталог в git не входит.

У собранного приложения каталог `models` лежит рядом с исполняемым файлом: на macOS внутри `AudioSep.app`, на Windows рядом с `AudioSep.exe`, на Linux рядом с `AudioSep`. Это не временный каталог сборки.

Другой путь задаётся аргументами `--separator` и `--clap`. Каждый аргумент можно передать отдельно: второй файл остаётся по умолчанию. Перед открытием окна приложение проверяет, что файлы есть. Если файла нет, показывается стандартное окно ошибки, и после OK приложение закрывается. Сами модели загружаются при первом отделении.

## Включение AudioSep

Способ включить код AudioSep в этот репозиторий пока не выбран: Python-пакет, git submodule или перенос части кода. До этого решения требования не задают путей и окружений вне репозитория.

## Настройки

Файл настроек приложения пока не выбран. Код его не читает.

## Поддерживаемые форматы

Приложение открывает и сохраняет аудиофайлы MP3, WAV и OGG. Формат задаёт расширение.

Модель AudioSep принимает и отдаёт моно WAV 32 кГц. Адаптер перекодирует аудиофайл пользователя в этот вид и результат обратно в аудиофайл.

Это единственное место, где перечислены форматы. В остальных требованиях достаточно слова «аудиофайл».

## Поведение первой версии

1. Пользователь указывает аудиофайл и текстовый запрос.
2. Разделение идёт в фоне, окно остаётся отзывчивым. Пока оно идёт, выбор файла, текст запроса, галка, кнопка «Отделить» и «Открыть папку» заблокированы. После завершения они снова доступны.
3. Отделённая дорожка сохраняется рядом с исходником с суффиксом `_separated`. Галка дополнительно сохраняет запись без этого звука с суффиксом `_without`: из исходной волны вычитается отделённая, обе вещественные и одной длины. Если пик разности больше 0,99, она ослабляется до 0,99.
4. Ошибка загрузки модели или разделения показывается текстом в окне.

Запрос передаётся в AudioSep как есть. Модель обучена на описаниях на английском.

## Границы модулей

- `src/audiosep_app/ui/` — виджеты и сигналы. Этот пакет не импортирует PyTorch и AudioSep.
- `src/audiosep_app/separation/` — чтение аудиофайла, вызов ONNX-разделения и запись результата. Этот пакет не импортирует PySide6.
- Окно просит разделить файл. Адаптер сохраняет аудиофайл или поднимает ошибку с понятным текстом.

Модели читаются из каталога приложения, см. раздел «Модели». Код AudioSep из соседнего репозитория адаптер не импортирует.

## Проверки

- Тесты подменяют адаптер и не скачивают веса.
- Публичные функции аннотированы типами.
- Перед завершением задачи, которая меняет поведение или структуру, в `CHANGELOG.md` есть запись в секции `[Unreleased]`.

Команды:

```shell
uv sync
uv run ruff check src tests
uv run pytest
```
